Context: the CURRENT shipped model-failover implementation (already committed, tested, working) does failover via gateway-controller-built Envoy `envoy.clusters.aggregate` clusters + native `retry_priority`, with a policy hook (`OnRequestBody`) setting an `x-target-upstream` header via the SDK's `UpstreamName` field to pick which cluster Envoy routes to. This works, but has a real, currently-*validated-against-rather-than-fixed* limitation: an LlmProxy's aliased/loopback upstreams (which distinguish different providers only by request path/BasePath, all sharing one loopback address) can't safely be used as aggregate-cluster members, because Envoy's aggregate-cluster retry operates below routing and can't vary the request path per member — so LlmProxy is currently restricted to zero-fallback dispatch only, enforced by a registration-time validator (`ValidateModelFailoverAggregateMembersHaveNoBasePath` in `gateway/gateway-controller/pkg/config/model_failover_validator.go`).

The plan doc proposes replacing this with Envoy's native `InternalRedirectPolicy`: instead of pre-building aggregate clusters, a policy's `OnResponseHeaders` hook would inspect the failed response (status code AND optionally the response body, e.g. `error.code`) and return a new `RetryWithUpstream` SDK action; the gateway-runtime kernel would translate that into an ext_proc `ImmediateResponse` carrying HTTP 307 plus an `x-target-upstream` header naming the fallback cluster; Envoy's `InternalRedirectPolicy` (configured on the route) would then intercept that 307 before it ever reaches the downstream client, and re-run the whole route/filter chain against the new header — meaning each retry gets a full, correct route re-evaluation (fixing the BasePath problem structurally) instead of Envoy's lower-level aggregate-cluster retry.

These are two different code paths in Envoy (ext_proc `ImmediateResponse` typically becomes a "local reply" short-circuit; `InternalRedirectPolicy` lives in the router filter and is documented for real upstream responses) — it is NOT confirmed that they're wired together.
